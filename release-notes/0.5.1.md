OpenBao Operator 0.5.1 adds OpenBao 2.7.0 compatibility, updates the default
validation target to OpenBao 2.6.3, and includes lifecycle fixes and dependency
updates since 0.5.0.

### What 0.5.1 changes

OpenBao 2.6.3 becomes the default validation target. OpenBao 2.7.0 adds external
KMS plugins for seals that earlier OpenBao versions included in the server. The
operator checks for a matching plugin before preparing a 2.7 workload or starting
an upgrade. It also accepts plugin metadata that OpenBao 2.7 can infer, while
retaining the required metadata for earlier versions.

The candidate includes the backup retention and partial-upload fixes, rolling
upgrade conflict retries, BlueGreen rollback and abort guards, restore status
preservation, readiness checks, and dependency updates merged since 0.5.0.

### Upgrade from 0.5.0

Finish active OpenBao upgrades, backups, and restores before updating the
operator. Take and verify a current backup. Review the generated CRD comparison
and qualification results for the final candidate commit.

The candidate retains the 0.5.0 API wire format. The plugin `version`,
`binaryName`, and `sha256sum` fields become optional in the CRD. Runtime
validation still requires them when the selected OpenBao version needs them.

Upgrade the operator before changing an OpenBao cluster to 2.7.0. For AWS KMS,
Azure Key Vault, Google Cloud KMS, OCI KMS, and PKCS#11 seals, declare the matching
external KMS plugin and provide its runtime dependencies before changing the
server version. Verify access to the existing seal key and qualify the exact
plugin version against a restored copy of the cluster data.

OpenBao 2.7 also removes some built-in authentication and secrets plugins.
Inventory enabled plugins before the server upgrade. Follow the
[OpenBao 2.7 migration procedure](https://dc-tec.github.io/openbao-operator/docs/operate/openbao-270/)
for the operator configuration and upstream migration references.

The SoftHSM fixture uses PKCS#11 plugin 0.1.0. Qualification does not cover vendor
HSMs, cloud KMS access, or the PKCS#11 0.2.0 root-key rewrap transition. The guard
against pre-2.6 to 2.6-or-newer BlueGreen transitions remains in place.
