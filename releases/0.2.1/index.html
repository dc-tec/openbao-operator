0.2.1

0.2.1

Published 2026-05-18.

Open

0.2.1 is a focused patch release for the 0.2 release line. It is intended for operators who need the Helm RBAC label fix or declarative OCI plugin auto-download support before the broader 0.3.0 release.

Highlights​

  • Fixed generated Helm RBAC labels so duplicate labels are not emitted in the rendered chart output.
  • Fixed OCI plugin auto-download by mounting a writable pod-local plugin directory at /openbao/plugins.
  • Added focused E2E coverage for declarative OCI plugin registration and the writable plugin directory mount.

Operational Notes​

  • Declarative OCI plugin auto-download requires OpenBao 2.5.0 or newer.
  • OCI plugin downloads happen inside the OpenBao runtime. Make sure the OpenBao pods have registry egress, and use a reachable mirror when running in private or disconnected environments.
  • spec.configuration.plugin.downloadBehavior accepts OpenBao's supported values: fail or continue.
  • Downloaded plugins are stored on ephemeral pod-local storage and should be treated as a startup cache, not durable plugin storage.

Upgrade from 0.2.0​

Apply the 0.2.1 CRDs before upgrading the controller or Helm chart:

kubectl apply -f https://github.com/dc-tec/openbao-operator/releases/download/0.2.1/crds.yaml

Then upgrade the Helm release:

helm upgrade openbao-operator oci://ghcr.io/dc-tec/charts/openbao-operator \
  --version 0.2.1 \
  --namespace openbao-operator-system \
  --reuse-values

Bug Fixes​

  • helm: deduplicate generated RBAC labels (069d9b4)
  • workload: mount a writable OCI plugin directory for OpenBao plugin auto-downloads (069d9b4)
  • api: align plugin downloadBehavior validation with OpenBao supported values, fail and continue (069d9b4)
